# AI-Based Landslide Risk Monitor — Northeast India (NER)

A landslide **susceptibility** model: give it terrain/rainfall/vegetation data for a location, it gives back a **% probability** the location is landslide-prone. Built entirely from free public data — no physical sensors needed.

## Files in this project

| File | Purpose |
|---|---|
| `NER_Landslide_Risk_Model.ipynb` | Google Colab notebook — data collection, feature extraction, model training, risk map, model export |
| `app.py` | Streamlit web app — loads the trained model and serves live predictions |
| `requirements.txt` | Python packages needed to deploy `app.py` |
| `landslide_model.pkl` / `landslide_model_features.pkl` | **Generated by the notebook** — you must run the notebook first and download these two files |

## Part 1 — Run the notebook in Google Colab

1. Go to https://colab.research.google.com → **File → Upload notebook** → upload `NER_Landslide_Risk_Model.ipynb`.
2. Run cells top to bottom (**Runtime → Run all**, or cell by cell to watch each step).
3. **Data collection (Step 1–3):** the notebook tries to download NASA's free Global Landslide Catalog and filters it to the NER bounding box. If that fails (network/endpoint issues), it automatically falls back to a synthetic dataset clustered around known NER landslide hotspots, so the notebook still runs end-to-end.
4. **Feature extraction (Step 4):** uses Google Earth Engine (GEE) to pull real elevation, slope, rainfall, and vegetation data.
   - To use real GEE data: sign up free at https://code.earthengine.google.com/, create a Google Cloud project, and replace `"YOUR-GCP-PROJECT-ID"` in the notebook with your project ID.
   - If you skip this, set `USE_GEE = False` and the notebook uses a realistic synthetic feature generator instead — fine for learning/demo, not for a real deployment.
5. **Model training (Step 6):** trains and compares 3 algorithms, picks the best by AUC.
6. **Risk map (Step 7):** builds an interactive heatmap of the whole NER region.
7. **Export (Step 8):** downloads `landslide_model.pkl` and `landslide_model_features.pkl` to your computer.

## The algorithms — what they are and why they're used

This is a **binary classification** problem: landslide (1) vs. stable (0), and we want the **probability**, not just the label.

### 1. Logistic Regression (baseline)
Fits a straight decision boundary and passes it through a sigmoid function to output a probability directly. Fast, simple, and interpretable — used here as a sanity-check baseline. Struggles when risk depends on *combinations* of features (e.g., steep slope is only dangerous *together with* high rainfall and low vegetation).

### 2. Random Forest
Builds hundreds of decision trees, each on a random subset of the data and features, then averages their votes. Captures non-linear interactions between slope, rainfall, and vegetation well, is robust to noisy/outlier data, and gives you **feature importance** (which factor matters most).

### 3. XGBoost (Gradient Boosted Trees)
Builds trees **sequentially** — each new tree specifically corrects the mistakes of the previous ones. This is the algorithm most published landslide-susceptibility-mapping (LSM) research papers use as their top performer, because it typically achieves the highest accuracy on structured/tabular geospatial data like this.

### Evaluation metric: ROC-AUC
Area Under the ROC Curve — measures how well the model separates landslide points from stable points across all probability thresholds. 1.0 = perfect, 0.5 = random guessing. Published LSM studies typically report 0.80–0.95. The notebook plots ROC curves for all three models side by side and automatically picks the best one.

### Features used
| Feature | Why it matters |
|---|---|
| Elevation | Higher elevations in NER = steeper surrounding terrain |
| Slope | The single strongest predictor — steeper slopes fail more easily |
| Aspect | Slope-facing direction affects sun exposure, moisture retention |
| Annual rainfall | Water saturation is the main landslide *trigger* in NER's monsoon climate |
| NDVI (vegetation greenness) | Roots stabilize soil — deforested slopes are far more prone to failure |
| Land cover class | Built-up/cropland vs. forest changes slope stability |

## Part 2 — Deploy as a live website (Streamlit Community Cloud, free)

**Streamlit Community Cloud** is the easiest free option — no server management, deploys straight from GitHub.

### Step-by-step

1. **Create a GitHub repo**
   - Go to https://github.com/new, create a public repo, e.g. `ner-landslide-risk`.

2. **Add these files to the repo**
   - `app.py`
   - `requirements.txt`
   - `landslide_model.pkl` (downloaded from the Colab notebook)
   - `landslide_model_features.pkl` (downloaded from the Colab notebook)

   You can do this via the GitHub web UI ("Add file → Upload files") or with git:
   ```bash
   git clone https://github.com/YOUR_USERNAME/ner-landslide-risk.git
   cd ner-landslide-risk
   # copy app.py, requirements.txt, landslide_model.pkl, landslide_model_features.pkl here
   git add .
   git commit -m "Initial landslide risk app"
   git push
   ```

3. **Deploy on Streamlit Cloud**
   - Go to https://share.streamlit.io/ and sign in with GitHub.
   - Click **"New app"**.
   - Select your repo, branch `main`, and set **Main file path** to `app.py`.
   - Click **Deploy**.
   - In 1–2 minutes you'll get a live URL like `https://ner-landslide-risk.streamlit.app`.

4. **Test it** — open the URL, pick a preset location or enter values manually, click "Calculate landslide risk", and you'll see the % risk with a color-coded level.

### Alternative deployment options
- **Hugging Face Spaces** (also free, supports Streamlit) — https://huggingface.co/new-space, choose "Streamlit" as the SDK, upload the same files.
- **Render.com** — free tier, more control, needs a `Procfile` (`web: streamlit run app.py --server.port $PORT`).

## Important limitations (be upfront about these if presenting this project)

- This is a **static susceptibility** model — it scores *inherent* terrain risk, not "it will slide in the next 24 hours." For a true early-warning system you'd combine this with live rainfall data (e.g., IMD or OpenWeatherMap APIs) and rainfall intensity-duration thresholds.
- If the notebook fell back to synthetic data at any step (no internet access to NASA GLC, or GEE not set up), the model quality is for demonstration only — for a real deployment, use verified GSI landslide inventory data and authenticated GEE feature extraction.
- Model accuracy depends heavily on how many *real* landslide points you can source — more labeled data = better model. Consider requesting the GSI (Geological Survey of India) landslide inventory for NER directly for a production version.
